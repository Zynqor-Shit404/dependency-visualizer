
# Dependency Visualizer

CLI-приложение для изучения зависимостей пакетов Alpine Linux.
Проект выполняется поэтапно в рамках практической работы,
вариант 11.

## Этап 1

На первом этапе приложение:

- читает настройки из XML-файла;
- проверяет параметры конфигурации;
- выводит параметры в формате ключ=значение;
- сообщает об ошибках конфигурации.

Получение зависимостей и создание графа будут реализованы
на следующих этапах.


## Этап 2

На втором этапе реализована основная логика получения данных:

- Приложение извлекает информацию о прямых зависимостях для заданного пакета.
- Используется формат пакетов **Alpine Linux (apk)**.
- Информация запрашивается строго для **конкретной версии** пакета, указанной в конфигурации (`package_version`).
- Для получения данных используется URL-адрес репозитория из конфигурации.
- **Важно:** Сторонние менеджеры пакетов и библиотеки для работы с зависимостями не используются (реализован собственный парсинг индексов репозитория).
- Результат (список прямых зависимостей) выводится на экран.

Получение транзитивных зависимостей и создание графа будут реализованы
на следующих этапах.


## Этап 3. Построение графа транзитивных зависимостей

Реализовано построение графа зависимостей пакетов.

Используется алгоритм поиска в ширину (BFS) с рекурсивным обходом.

Выполняется поиск прямых и транзитивных зависимостей пакета.

Поддерживается фильтрация пакетов по заданной подстроке package_filter.

Обрабатываются циклические зависимости с помощью множества посещённых пакетов.

Реализован тестовый режим: вместо URL репозитория используется локальный файл test_repository.txt.

В тестовом репозитории используются имена пакетов, состоящие из заглавных латинских букв.

Результат выводится в консоль в формате пакет -> зависимости.

Пример тестового репозитория

A: B C
B: D
C: D E
D: A
E:

Для запуска приложения в тестовом режиме используется команда:

python -m src.main

Результат

A -> B, C
B -> D
C -> D, E
D -> A
E -> (нет)


## Этап 4. Поиск обратных зависимостей

Реализован дополнительный режим поиска обратных зависимостей пакетов.

**Обратные зависимости** — это пакеты, которые прямо или транзитивно зависят от выбранного пакета.

### Реализация

- Добавлен аргумент командной строки `--reverse`, принимающий имя пакета.
- Для поиска используется обход обратного графа зависимостей.
- Повторное посещение пакетов предотвращает зацикливание при наличии циклических зависимостей.
- Результаты выводятся в консоль.
- Если обратные зависимости не найдены, выводится соответствующее сообщение.

### Запуск

```bash
python -m src.main --reverse D
```

### Пример результата

Для тестового репозитория:

```text
A: B C
B: D
C: D E
D: A
E:
```

При поиске обратных зависимостей пакета `D` результат будет следующим:

```text
Обратные зависимости пакета D:
- A
- B
- C
```

### Проверка

Для проверки необходимо запустить программу с разными именами пакетов, в том числе с пакетом, у которого нет обратных зависимостей, и убедиться, что циклические зависимости не приводят к бесконечному обходу.

**Примечание:** поиск выполняется в построенном графе зависимостей и учитывает установленный фильтр `package_filter`.

## Настройки

Файл конфигурации: `config.xml`.

- `package_name` — название пакета;
- `repository` — URL или путь к тестовому репозиторию;
- `test_mode` — режим тестового репозитория;
- `package_version` — версия пакета;
- `output_image` — имя выходного PNG-файла;
- `package_filter` — подстрока фильтрации.

## Запуск

Требуется Python 3.10 или новее.

```bash
./run.sh
```

Можно указать другой конфигурационный файл:

```bash
./run.sh --config config.xml
```

## Тестирование

```bash
python3 -m unittest discover -s tests -v
```

## Структура

- `src/` — исходный код приложения;
- `tests/` — автоматические тесты;
- `config.xml` — параметры запуска;
- `run.sh` — скрипт запуска.
